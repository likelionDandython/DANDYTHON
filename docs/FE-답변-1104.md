꼼꼼한 답변 감사해요! 답변을 받은 날 팀에서 구조를 몇 가지 바꾸기로 해서, **바뀐 결정**과 **FE가 이미 바꾼 것**을 같이 정리했어요. 바뀐 명세서(같이가요 기능명세서, 11/4 개정)와 화면 시안도 같이 확인 부탁드려요 🙏

## A. 계정 하나 + 모드 (가장 중요)

20대도 본인 진료로 동행이 필요할 수 있고, 봉사하던 학생이 가족 동행을 요청할 수도 있어서 **한 계정이 두 모드를 오가는 구조**로 바꿨어요.

- 가입: 이름·휴대폰·이메일·비밀번호 + **공통 약관만** 받아요 (역할을 묻지 않아요)
- 가입 후 **"오늘은 무엇을 할까요?"** → 동행 요청 모드 / 동행하기 모드
- 각 모드에 **처음 들어갈 때** 그 모드의 약관을 받아요
- 홈 상단 버튼과 MY에서 언제든 모드 전환, 로그인하면 **마지막에 쓴 모드**로 열려요

**BE에 부탁드리는 변경**

| 순위 | 변경 | 내용 |
|---|---|---|
| 높음 | 권한 검사 | `hasRole(...)` 대신 **데이터로 검사**해 주세요. 봉사 신청·동행 진행 = 봉사자 프로필이 있는 사람 / 신청자 목록·수락·요약 열람·봉사시간 승인 = **그 요청을 등록한 사람** |
| 높음 | 가입 | `SignupRequest.role`을 **선택값**으로 (최종적으로는 제거). 필수 약관은 공통 3개(`TERMS`, `PRIVACY`, `THIRD_PARTY`)만 |
| 중간 | 모드별 약관 | `POST /api/users/me/consents` `{ "consents": [{ "item": "PROFILE_PUBLIC", "agreed": true }] }` |
| 중간 | 마지막 모드 | `PATCH /api/users/me` `{ "lastMode": "REQUEST" \| "VOLUNTEER" }`, `GET /users/me`·로그인 응답에 `lastMode` |

모드별 필수 약관은 이렇게 바꿨어요.

- 동행 요청 모드: `SUMMARY_RECEIVE`, `HEALTH_INFO` 필수 / `PROXY_CONFIRM`은 **가족을 위해 요청할 때만** 필수 / `SUMMARY_SHARE` 선택
- 동행하기 모드: `PROFILE_PUBLIC`, `VOLUNTEER_PLEDGE`, `CONFIDENTIALITY` 필수 / `SCHOOL_VERIFY` 선택

> **지금 호환 방법**: BE가 바뀌기 전까지 FE는 **가입할 때 처음 고른 모드로 `role`을 채워** 기존 가입 API를 불러요. 그래서 첫 모드는 지금 API로 동작하고, **두 번째 모드로 전환한 뒤의 API 호출**은 위 권한 변경이 있어야 동작해요. `users/me/consents`, `PATCH users/me`는 실패해도 FE가 화면을 막지 않게 해 뒀어요.

## B. 나 / 가족 요청

| 순위 | 변경 | 내용 |
|---|---|---|
| 높음 | 요청 대상 | `POST /api/requests`에 `targetType: "SELF" \| "FAMILY"` 추가. `seniorId`는 **FAMILY일 때만** (지금 `@NotNull`) |
| 높음 | 요청 등록자 | `requests.requester_id` 저장, `GET /api/requests/{id}` 응답에 `requesterId`, `targetType` |
| 높음 | 내 요청 신청 차단 | 본인이 등록한 요청에 신청하면 에러 `OWN_REQUEST` |
| 낮음 | 이동 방법 | `travelMode: "BUS_TRAIN" \| "TAXI" \| "FAMILY_CAR"` (저장·상세 응답만) |

- 본인 요청이면 `senior` 자리에 **요청자 본인 정보**(이름·나이·시군)를 채워 주시면 FE 화면을 그대로 쓸 수 있어요. 나이·시군이 가입 정보에 없으면 요청 때 받는 방법도 괜찮아요 (편한 쪽 알려주세요)
- **자동 확정 없음**: 본인 요청도 요청자가 신청자 프로필을 보고 수락해요. 명세의 "어르신 직접 등록 시 첫 신청자 자동 확정"은 삭제됐어요
- 비용은 앱에서 정산하지 않아요 (차비·진료비·약값은 동행받는 분이 직접 결제). 관련 API는 필요 없어요

## C. 알림은 MVP 제외

알림을 넣기로 해 주셨는데, 팀에서 **알림은 발표용 확장 기능**으로 빼기로 했어요. 11/6 마감 안에 FE가 Firebase SDK·서비스 워커·`manifest.json`·HTTPS 배포까지 붙이기 어렵고, 아이폰은 홈 화면에 추가해야만 동작하는 제약도 있어서요.

- **FCM 푸시 토큰 API, 알림 목록, 알림 설정 5개 모두 안 만드셔도 돼요.** 혹시 이미 만드셨다면 그대로 두셔도 FE는 호출하지 않아요
- FE에서 홈 벨 아이콘, MY의 알림 설정 스위치를 뺐어요
- 체크리스트 **`completedAt`은 꼭 부탁드려요!** 요청자의 동행 현황 화면에서 단계별 시각으로 쓰고 있어요

## D. 호칭 (문구 맞춰 주세요)

나이와 관계없이 쓰는 서비스가 돼서 호칭을 바꿨어요. 서버가 만드는 문구(에러 메시지, AI 요약 프롬프트 등)에도 맞춰 주세요.

| 이전 | 이후 |
|---|---|
| 어르신 | **동행받는 분** (이름 뒤에는 "님": 김순자 님) |
| 보호자 | **요청자 / 요청한 분** |
| 부모님 | **가족** |
| (AI 요약 출력) 보호자가 할 일 | **요청자가 챙길 일** |

에러 메시지 예: `CONSENT_REQUIRED` → "동행받는 분의 동의가 필요해요."

DB·코드의 이름(`seniors`, `guardian` 등)은 그대로 두셔도 괜찮아요. 화면에 보이는 문구만 맞춰 주시면 돼요.

답변대로 **업로드 없이 캐릭터 고정**으로 맞췄어요. FE는 `photoUrl`을 빈 문자열로 보내요 (안 보내는 게 더 편하면 알려주세요).

## F. BE 답변 반영 현황 (FE 브랜치 `feat/fe-account-mode`, PR #7)

| BE 답변 | FE 반영 |
|---|---|
| 1. 봉사자 추가 정보 | 프로필 화면에 활동 지역·요일·이동 방법·할 수 있는 도움 추가, `GET /volunteers/me`로 수정 화면 불러오기. 신분증·교육·1365·승인 대기 화면 **삭제** |
| 2. 실시간 위치 제외 | 동행 진행·동행 현황 화면의 **지도 삭제**, 체크리스트로 대체 |
| 3. 알림 | 위 C처럼 **MVP 제외** |
| 4. 어르신 앱 제외 | `/elder/*` 화면 **삭제**. 본인 요청은 동행 요청 모드의 "나"로 처리 |
| 5. 인증 | 이메일+비밀번호 유지, 새로고침 때 `GET /users/me`로 이름·프로필 완성 여부 복구 |
| 7. 사진 | 캐릭터 고정 |
| 8. 기타 | `expectedHours`, `recognizedMinutes`/`approvedMinutes`(활동 내역에 인정 시간 표시), 감사 메시지 `{message, createdAt}` 타입 반영 |
| 9. 에러 코드 | 추가 7개 문구 매핑, 늦은 취소 문구 "동행 2일 전 이후 취소는 기록에 남아요" |

**`abilities` 값 목록** (FE가 보내는 값)

`WALK_ASSIST`, `WHEELCHAIR`, `EXAM_ESCORT`, `PHARMACY`, `RIDE_HOME`, `SIGN_LANGUAGE`

**`regions` 값** (화면 선택지): 대구 중구, 대구 동구, 대구 서구, 대구 남구, 대구 북구, 대구 수성구, 대구 달서구, 대구 달성군, 군위군, 칠곡군, 경산시, 영천시

## G. 배포·CORS

- FE 로컬 포트는 Vite 기본 **5173** 그대로예요 (이미 허용돼 있어요)
