# FE → BE 요청·확인 사항

> `api-spec.md (v0.1, 10/31)` 기준으로 FE를 API에 연동하면서 정리한 내용입니다.
> FE는 명세에 있는 기능을 모두 연결했고, 아래는 **명세에 없거나 불명확해서** BE 확인·추가가 필요한 항목입니다.

## 0. 11/4 변경: 계정 하나 + 모드, 나/가족 요청 (가장 먼저)

팀 결정(명세서 11/4 개정)에 맞춰 FE를 바꿨습니다. **아래가 BE에 반영되기 전까지는 FE가 가입 때 처음 고른 모드로 `role`을 채워 보내서 기존 API와 호환**되게 해 두었습니다.

| 순위 | 변경 | 내용 |
|---|---|---|
| 높음 | 권한 검사 | `@PreAuthorize("hasRole(...)")` 대신 **데이터로 검사**: 봉사 신청·동행 진행은 봉사자 프로필이 있는 사람, 신청자 목록·수락·요약 열람·승인은 **요청 등록자(`requesterId`)** |
| 높음 | 본인 요청 | `POST /requests` body에 `targetType: 'SELF' \| 'FAMILY'` 추가, `seniorId`는 FAMILY일 때만(지금 `@NotNull`) |
| 높음 | 요청 등록자 | `requests.requester_id` 저장, `GET /requests/{id}` 응답에 `requesterId`, `targetType` 포함 |
| 높음 | 내 요청 신청 차단 | 본인이 등록한 요청에 `POST /requests/{id}/applications` → 에러 코드 `OWN_REQUEST` |
| 중간 | 가입 | `SignupRequest.role`을 선택값으로 (최종적으로는 제거) |
| 중간 | 모드별 약관 | `POST /users/me/consents` `{ consents: [{item, agreed}] }` — 모드에 처음 들어갈 때 받은 동의 저장 |
| 중간 | 마지막 모드 | `PATCH /users/me` `{ lastMode: 'REQUEST' \| 'VOLUNTEER' }`, 로그인·`/users/me` 응답에 `lastMode` |
| 낮음 | 이동 방법 | `POST /requests`에 `travelMode: 'BUS_TRAIN' \| 'TAXI' \| 'FAMILY_CAR'` (저장·상세 응답만) |
| 결정 | 자동 확정 없음 | 본인 요청도 요청자가 신청자를 보고 수락 (명세의 "어르신 직접 등록 시 첫 신청자 자동 확정" 삭제) |

FE가 쓰는 새 필드·엔드포인트는 `FE/src/api/types.ts`, `FE/src/api/services.ts`에 `BE 추가 필요` 주석으로 표시했습니다.

## 1. 봉사자 가입 추가 정보 (명세에 없음)

봉사자 가입 2·3단계 화면에 입력/표시되는 값인데 `signup`, `PUT /volunteers/me`에 필드가 없습니다.

| 화면 값 | 비고 |
|---|---|
| 활동 지역 (대구 북구, 칠곡군 …) | 다중 선택 |
| 가능한 요일 | 다중 선택 |
| 이동 방법 (대중교통 / 자차) | 다중 선택 |
| 할 수 있는 도움 | `Need` enum과 매핑 가능한지 (수어 가능 등 추가 항목 존재) |
| 신분증 확인 | 인증 방식(업로드? 외부 연동?)과 API |
| 동행 봉사 교육 이수 (영상 3편) | 시청 진행률 저장 API |
| 1365 자원봉사 연동 (선택) | 연동 방식 |
| 승인 심사 상태 | 가입 후 "승인 대기" 화면이 있음. 승인 전 신청 가능 여부, 상태 조회 방법 |

→ 지원 범위를 알려주시면 FE에서 화면을 맞추겠습니다. 지원하지 않는 항목은 FE에서 제거합니다.

## 2. 실시간 위치 공유 (명세에 없음)

- 봉사자 동행 화면(`지도 + "보호자에게 실시간 위치 공유 중"`), 보호자 실시간 현황 화면에 지도가 있습니다.
- 필요하면: 위치 전송 `POST`, 최신 위치 조회 `GET`, 위치 정보 이용 동의 항목(`consents`) 추가.
- MVP에서 제외한다면 FE에서 지도를 제거합니다.

## 3. 알림 (명세에 없음)

- **11/5 결정: 알림은 유지.** FCM 웹 푸시·알림 목록·설정 모두 BE 11/4 답변 3번대로 진행해요. 자세한 내용은 `docs/FE-답변-1104.md` C항목.

- 보호자 MY의 "알림 받을 순간" 스위치 5개(출발·도착·진료 종료·귀가·대기 소식), 홈의 벨 아이콘.
- 필요하면: 알림 설정 조회/저장, 알림 목록, 푸시 방식.
- 보호자 소식 피드(`"9:12 접수 마쳤어요"` 같은 문구)는 현재 `checklist` 완료 항목으로 대체했고 **단계별 완료 시각은 받을 수 없음**. 단계별 시각(`completedAt`)을 체크리스트에 포함해 주실 수 있나요?

## 4. 어르신 앱 (`/elder/*`)

- 어르신 본인 가입(전화번호), 병원·날짜 선택 신청, 봉사자 배정 확인, 지난 기록 화면이 설계되어 있습니다.
- 명세에는 어르신 계정이 없고 보호자가 `POST /seniors`로 등록하는 구조입니다. (명세 하단 "어르신 직접 등록 MVP에서 뺄지" 항목)
- **11/4 결정: 별도 어르신 앱은 MVP에서 제외.** 본인 요청은 동행 요청 모드에서 "나"를 고르는 방식으로 합쳤습니다. FE 라우트에서 `/elder/*`를 뺐습니다 (파일은 참고용으로 남김).
- 보호자 가입 3단계의 "초대 문자로 어르신과 연결" 기능도 같은 이유로 보류 상태입니다.

## 5. 인증·계정

- **로그인 방식**: FE 디자인은 휴대폰+인증번호, 카카오 로그인이었으나 명세에 맞춰 **이메일+비밀번호**로 바꿨습니다. 휴대폰 인증·카카오 로그인이 필요하면 API 추가 요청.
- 휴대폰 번호 본인 인증 (가입 화면의 "인증 완료")
- 비밀번호 찾기/재설정, 로그아웃(서버 토큰 무효화 필요 여부)
- **토큰 만료 정책**: 만료 시 FE는 401 수신 → 로그아웃 처리합니다. 리프레시 토큰이 있나요?
- 내 정보 조회 (`GET /users/me` 등): 새로고침 시 이름·역할 복구에 사용 (현재는 로그인 응답을 localStorage에 저장)

## 6. 병원

- `GET /hospitals`는 5곳 고정입니다. FE의 "다른 병원 찾기"(검색) 기능이 필요한지.
- 진료과: 문자열 자유 입력 vs enum (명세 "팀 확인 필요" 항목). 현재 FE는 자유 입력.

## 7. 사진·파일

- **11/4 확정: 사진 업로드 없음. 봉사자 프로필은 서비스 캐릭터 고정 (FE에서 표시).** 얼굴 사진은 확장(P1). FE는 `photoUrl`을 빈 문자열로 보냅니다.

## 8. 기타 편의 기능

- 게시판 "가까운 순" 정렬/필터: 위치 기반이므로 제외하였습니다. 필요 시 정렬 파라미터.
- 봉사 활동 내역에 인정 시간: `GET /applications/me`에는 시간이 없음. 활동 내역 목록에 `recognizedMinutes`/`approvedMinutes` 포함 가능한지.
- 요청 상세 응답에 `expectedHours` 포함 가능한지 (게시판 목록에는 있으나 상세에는 없음).
- 감사 메시지 목록에 작성 일자/보호자 정보가 필요하면 추가.
- 여러 어르신 등록 시 보호자 가입 화면의 "한 분 더 등록하기"는 `POST /seniors` 반복 호출로 처리 예정 (문제 없으면 확인만).

## 9. 명세 확인 질문 (연동 시 오류 가능성)

1. **consents 필수 항목**: 아래처럼 FE에서 보냅니다. 서버 필수 판정 기준이 맞는지 확인 부탁드립니다.
   - 보호자: `TERMS`, `PRIVACY`, `THIRD_PARTY`, `PROXY_CONFIRM`, `HEALTH_INFO` (필수로 표시) / `SUMMARY_SHARE`, `SUMMARY_RECEIVE` (선택으로 표시)
   - 봉사자: `TERMS`, `PRIVACY`, `THIRD_PARTY`, `PROFILE_PUBLIC`, `VOLUNTEER_PLEDGE`, `CONFIDENTIALITY` (필수) / `SCHOOL_VERIFY` (선택)
   - **`SUMMARY_RECEIVE`가 필수인지?** 
   - 항목이 `agreed:false`로 오는 경우도 저장되는지 (현재 선택 항목은 false로도 전송)
2. **어르신 `region`**: FE가 주소 문자열에서 정규식으로 `○○시/군`을 뽑아 보냅니다 (예: "경북 의성군 …" → `의성군`). 서버가 기대하는 형식(시·군 이름만)이 맞는지.
3. **어르신 `phone`**: 없는 경우 빈 문자열(`""`)을 보냅니다. 허용되는지, 또는 null/생략이어야 하는지.
4. **봉사자 `age`**: 프로필 저장 시 만 나이를 보냅니다. (생년월일을 저장하지 않음. 만 18세 이상 검증은 FE가 선행)
5. **checkin/checkout 후 체크리스트**: 체크인하면 `MEET` 단계가 서버에서 자동으로 `done` 처리되는지, 아니면 FE가 `PATCH /step`으로 `MEET`도 완료해야 하는지. FE는 "체크리스트에서 첫 미완료 단계를 순서대로 PATCH"하는 방식이라 어느 쪽이든 동작합니다.
6. **마지막 단계(`SEE_OFF`) 이후 `checkout`**: FE는 모든 단계 완료 후 체크아웃을 호출합니다. 단계 미완료 상태에서 체크아웃하면 오류인지.
7. **요약 조회 `GET /visits/{id}/summary`**: 요약이 아직 생성되지 않았을 때 응답 (404 코드명?). FE는 `visit.hasSummary`가 false면 호출하지 않고 안내 문구를 보여줍니다.
8. **`POST /applications/{id}/accept`, `DELETE`류의 `lateCancel`** 표기 문구 등 UI 정책 (경고 문구 기준) 확인.
9. **날짜·시간**: `meetTime`은 `HH:mm`, `date`는 `yyyy-MM-dd`로 보내며 KST 기준입니다. 서버 시간대가 다르면 알려주세요.
10. **CORS / 배포 주소**: FE 개발 서버는 `/api`를 프록시합니다(기본 `http://localhost:8080`). 로컬 BE 포트, 배포 API 주소, CORS 허용 도메인을 알려주세요.
11. **에러 코드 목록**: FE에 한글 문구 매핑이 있는 코드는 `INVALID_INPUT`, `UNAUTHORIZED`, `FORBIDDEN`, `INVALID_STATUS`, `EMAIL_DUPLICATED`, `REQUIRED_CONSENT_MISSING`, `LOGIN_FAILED`, `SENIOR_NOT_FOUND`, `REQUEST_NOT_FOUND`, `PROFILE_INCOMPLETE`, `ALREADY_APPLIED`, `SCHEDULE_CONFLICT`, `CONSENT_REQUIRED` 입니다. 그 외 `*_NOT_FOUND` 등은 서버가 보낸 `message`를 그대로 표시합니다. 빠진 코드가 있으면 알려주세요.
