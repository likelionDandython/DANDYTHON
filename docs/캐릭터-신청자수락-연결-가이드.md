# 캐릭터 · 신청자 수락 화면 연결 가이드

기존(팀원이 만든) 파일은 **하나도 수정하지 않았어요.** 아래 새 파일만 추가했어요.

## 추가한 파일 (FE/src)
| 구분 | 파일 | 설명 |
|---|---|---|
| 캐릭터 | `components/common/Character.tsx` | 어르신·봉사자 캐릭터, 하트 아치 장면(`CharacterPair`), 원형 아바타(`CharacterAvatar`). **임시 캐릭터**예요(로고·캐릭터 미확정). 색은 CSS 변수 |
| 화면 | `screens/guardian/Applicants.tsx` | README 표의 "신청자 목록 + 수락" (`GuardianApplicants`)과, 선택 후 확정 전 안내 화면(`GuardianApplicantConfirm`) |
| 라우트 | `design/routes.tsx` | 화면 2개의 경로 (`/guardian/applicants`, `/guardian/applicants/confirm`) |
| 스타일 | `styles/design-tokens.css`, `styles/screens.css`, `design/styles.ts` | 새 변수와 이 화면에서 쓰는 클래스만. 기존 `index.css`, `tokens.css` 는 그대로 |

## README 지시와의 관계
- README "신청자 목록 + 수락 (우선순위 높음)": 신청자 프로필·신청 메시지 카드, 수락 버튼 → `GuardianApplicants`.
  `GET /requests/{id}/applications`, `POST /applications/{id}/accept` 를 기존 `applicationApi` 로 호출해요.
- README 에 없는 추가 부분: 신청 한 마디 말풍선, 신청자 없음 화면, `verified` 가 true 일 때만 보이는 "재학 인증" 배지(명세 PRF-02, 학교 이메일 인증), 캐릭터.

## 앱에 붙이는 방법 (팀이 직접 적용)
1. `routes.tsx` 의 `guardian` 섹션 `routes` 끝에 `...designRoutes.guardian` 추가.
2. 보호자 홈 "다가오는 일정"에서 모집 중(`RECRUITING`) 요청을 누르면 `/guardian/applicants?requestId={id}` 로 이동하게 연결.
   (지금은 기존 코드에서 `'/guardian/home'` 으로 가요.)
3. 확정이 끝나면 기존 `/guardian/confirmed?requestId=` 로 이동해요 (이미 연결돼 있어요).

## 서버 상태 (2026-11-04 배포 명세 기준)
배포된 서버(Swagger)에는 가입·로그인, 프로필(`/volunteers/me`), 어르신 등록, 병원 목록, 요청 등록(`POST /requests`)만 있어요.
이 화면에 필요한 `GET /requests/{id}`, `GET /requests/{id}/applications`, `POST /applications/{id}/accept` 는 아직 없어서,
**지금 서버에 연결하면 동작하지 않아요.** BE 가 만들면 그대로 연결돼요.

## 팀원 코드에서 같이 맞추면 좋은 문구
- 기존 `screens/guardian/Main.tsx` 의 봉사자 카드에 "신원 확인 완료 / 신원 확인 대기"가 있어요. BE 에서 신분증 확인은 제외됐고, 명세 PRF-02 는 "재학 인증" 배지예요. (이 PR 에서는 수정하지 않았어요.)

## 알려진 점
- 타입 검사만 통과했고, 화면 실행으로 확인하지는 못했어요.
- 이 범위에서는 "요청 취소", "봉사자 프로필 상세"로 가는 링크를 뺐어요(해당 화면이 이 브랜치에 없어요).
